# Agent Tool Protocol & Diagnostic Reasoning Specification

## 1. Overview
The **ivA Agent Core** operates as an in-process, schema-enforced diagnostic service inside NestJS (`backend/src/agent/`). It eliminates fragile out-of-process JSON regex parsing by using structured schemas and a pluggable LLM provider abstraction (`ILlmProvider`).

---

## 2. Pluggable Model Providers

The agent dynamically selects its inference backend via environment configuration:
- `LLM_PROVIDER=ollama`: Connects to local Ollama (`http://localhost:11434`) running models such as `qwen2.5:7b` or `llama3.1:8b` for air-gapped clinical deployments.
- `LLM_PROVIDER=openai`: Connects to OpenAI, Azure OpenAI, or OpenAI-compatible endpoints (vLLM, LM Studio) using JSON mode.
- `LLM_PROVIDER=mock`: Deterministic clinical reasoning engine for offline development, test automation, and zero-token benchmark verification.

## 3. Tool Protocol & Registry

All tools are exposed through `AgentToolsService` and can be invoked either by the agent reasoning loop or external Model Context Protocol (MCP) clients.

### 3.1. `search_knowledge_hybrid`
Executes multi-stage hybrid search across technical service manuals.
- **Parameters**:
  - `query` (string, required): Symptom, error code, or natural language question.
  - `instrumentId` (UUID, optional): Restrict search scope to a specific instrument.
  - `limit` (number, default 3): Number of chunks to return.
- **Returns**: Top RRF-fused chunks with page numbers, section headers, chunk types, and bounding box coordinates.

### 3.2. `get_component_specs`
Fetches hardware tolerances, telemetry tags, and replacement part numbers from the equipment ontology.
- **Parameters**:
  - `idOrPartNumber` (string, required): Component ID, name, or OEM part number (e.g. `948-230-01`).
- **Returns**: Full component hierarchy, parent subsystem, sensor/actuator specs, and spare parts.

### 3.3. `get_vault_entity`
Retrieves a Markdown knowledge object from the Obsidian vault.
- **Parameters**:
  - `id` (string, required): Entity ID (e.g. `ERR-E1045`, `PROC-PUMP-CALIBRATION`, `SB-2026-014`).
- **Returns**: Frontmatter properties, markdown body, inbound edges, and outbound edges.

### 3.4. `traverse_knowledge_graph`
Performs multi-hop graph traversal across the `KnowledgeEdge` relational table.
- **Parameters**:
  - `rootId` (string, required): Starting entity anchor.
  - `depth` (number, default 2, max 3): Traversal radius.
- **Returns**: Subgraph nodes and directed edges with semantic relationships (`AFFECTS`, `CAUSED_BY`, `RESOLVES`, `USES_PART`).

### 3.5. `inspect_provenance_page`
Inspects exact layout chunks and bounding boxes for a specific page of an authoritative PDF manual.
- **Parameters**:
  - `documentId` (UUID, required): Document ID.
  - `pageNumber` (number, required): 1-indexed page number.
- **Returns**: Page dimensions (`width` × `height`), raw text, and array of bounding boxes.

## 4. Evidence-First Clinical Reasoning Schema

Every diagnostic report generated by the agent must adhere to the following schema:

```typescript
export interface DiagnosticReport {
  summary: string;
  confidenceScore: number; // 0.0 to 1.0
  documentedFacts: Array<{
    statement: string;
    source: string;
    pageNumber?: number;
  }>;
  historicalObservations: Array<{
    observation: string;
    confidence: string;
  }>;
  deterministicRules: Array<{
    rule: string;
    status: 'COMPLIANT' | 'VIOLATED' | 'CHECK_REQUIRED';
  }>;
  aiHypotheses: Array<{
    hypothesis: string;
    probability: number;
    reasoning: string;
  }>;
  safetyAlerts: Array<{
    level: 'BIOHAZARD' | 'HIGH_VOLTAGE' | 'CAUTION';
    directive: string;
  }>;
  actionPlan: Array<{
    stepNumber: number;
    action: string;
    requiresFseApproval: boolean;
    partNumber?: string;
  }>;
}
```

---

## 5. Human-in-the-Loop Safety Consequentiality Rules

Any consequential field action requires explicit Field Service Engineer approval before machine state or parameters can be updated:
- Part replacement (`requiresFseApproval: true`).
- Sensor zero-offset / calibration parameter EEPROM write (`requiresFseApproval: true`).
- Status transition back to `OPERATIONAL` (`requiresFseApproval: true`).

---

## 6. Audit Tracing (`AgentExecutionTrace`)

Every diagnostic session writes an immutable audit record to PostgreSQL containing:
- `sessionId` & `instrumentId`
- `prompt`
- `provider` & `model`
- `toolsCalled` (ordered log with timestamps)
- `retrievedEvidence` (exact JSON dump of chunks and graph nodes)
- `finalResponse` (JSON report)
- `latencyMs` & `tokenCount`
